# caphome-dedup fixture — provenance & fidelity notes

## What this is
A **synthesized** (not captured) record/replay fixture for a **2-page** LJCMG CapHome enforcement
search in which **one record appears on both pages**. It drives the FULL Appendix B.1
`SearchEnforcementRecords` payload and exists to exercise the one search semantic no other search
fixture reaches: the `result`'s `distinct(newLinks)` de-dup, which reproduces the reference's
`HashSet<string> newLinks` (`HistoricalCrawler.cs:79`, `:99`). No Chromium, no live traffic.

- `manifest.json` — `form → page1 → page2`. The search click and the pagination click each emit a
  `POST CapHome.aspx` (the postback `waitForRequest` matches).
- `page1.html` — 3 data rows (`3 header + 3 data + 2 footer = 8 <tr>`): `d1-1`, `d1-2`, and the
  **shared** record `?id=shared`. Carries the `table.aca_pagination td:last-child a` anchor
  (`hasMorePages` true).
- `page2.html` — 2 data rows (`3 header + 2 data + 2 footer = 7 <tr>`): the **shared** record
  `?id=shared` again (byte-identical row — the same record), then `d2-1`. **No** pagination anchor
  (`hasMorePages` false → last page).
- `golden.json` — the expected `result` for `knownUrls=[]`, `priorCrawlComplete=false`.

Each grid holds `3 header + N data + 2 footer` rows, so the reference loop `for (i=3; i < count-2; i++)`
(`LJCMGClient.cs:127`) visits exactly the N data rows. Row urls are the naive `scheme://host + href`
concat (`:130`); both results states report the same `CapHome.aspx` url, so scheme/host resolve to
`https://aca-prod.accela.com` and the two `?id=shared` rows produce the **identical** url
`https://aca-prod.accela.com/LJCMG/Cap/CapDetail.aspx?id=shared`.

## The reference algorithm being reproduced (derive the golden from THIS, not intuition)
`HistoricalCrawler.goToNextPageCallback` (`:85-104`), flattened per page:

```
if (!HasMorePages) crawledToEnd = true;                       // :87
if (Results.Count == 0) return false;                         // :89
foreach (result in Results)                                   // :91
    if (knownUrls.Contains(result.Url)) return !crawledToEnd; // :93-95
    else newLinks.Add(result.Url);                            // :99   HashSet ⇒ a repeat url is a no-op
return HasMorePages;                                          // :103
```

The B.1 payload accumulates every scanned url into a **list** `newLinks` (`push`), then the `result`
applies `distinct(newLinks)` (`:901`) — first-occurrence-preserving, matching the `HashSet` (Appendix
C, design §14.1). `pages` accumulates the full per-page row array for every non-empty page reached and
is **not** de-duplicated: the shared row is present in both `pages[0]` and `pages[1]`.

## Per-case derivation (hand-executed over this fixture — `knownUrls=[]`, `priorCrawlComplete=false`)
`crawledToEnd` starts **false**.

| page | `!HasMorePages`→crawledToEnd | rows scanned (`newLinks.Add`) | return (:103) |
|---|---|---|---|
| 1 | stays false (`hasMorePages` true) | `d1-1`, `d1-2`, `shared` | `HasMorePages`=true → continue |
| 2 | **→ true** (:87, last page) | `shared` (repeat, HashSet no-op), `d2-1` | `HasMorePages`=false → stop |

- `newLinks` list (push order) = `[d1-1, d1-2, shared, shared, d2-1]` → `distinct(...)` =
  **`[d1-1, d1-2, shared, d2-1]`** (the second `shared` collapses; first-occurrence order kept).
- `crawledToEnd` = **true** (flipped on page 2, the last page).
- `pages` = **`[[d1-1, d1-2, shared], [shared, d2-1]]`** — 5 raw rows across 2 pages; `shared` present
  in both (the un-de-duplicated per-page arrays the reference handed the callback).
- Requests: `goto` + search + 1 pagination = **3** (the payload breaks on page 2 before the pagination
  `waitForRequest`, `hitKnown=false ⇒ break when !hasMorePages = !false = true`).

**This is the whole point of the fixture:** `newLinks` shows the shared url **once** while `pages`
shows the shared row **twice** — the `distinct(...)`/`HashSet` de-dup made observable, and distinct
from the "no duplicate urls" goldens of `caphome-search`/`caphome-multipage` where `distinct(...)` is
the identity.

## Golden provenance
`golden.json` was generated by executing the reference algorithm above (the callback + the
`LJCMGClient` do/while, `:121-167`) directly over this fixture's rows — the same derivation a
standalone C# harness produces — **not** copied from Crawldad's output. The acceptance test
(`SearchAcceptanceTests`) asserts Crawldad's output is byte-identical (canonicalized). Real-Chromium
parity is the Phase 4 gate (fake ≡ real, against a local fixture site); this file is a faithful
synthesis, not a capture.
